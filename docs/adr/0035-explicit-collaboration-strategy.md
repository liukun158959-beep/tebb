# 用户明确的协作策略优先于模型路由建议

#210按本批统一采用推荐方案的授权推进。真实v18对照中两种模式在进入只读循环前就被路由为direct；最后未派单，严格反馈拒绝。这不是Atlas循环质量对照通过。grilling事实调查已核对公开Bridge→Collaboration.action/send与预算/恢复链；领域仍使用既有用户目标和当前职责，无新增平行任务概念。

推荐答案已按用户授权采纳：认证send接受可选strategy=auto/delegate，缺省兼容旧请求。明确delegate限当前协作群，由群负责人协调，不扩展tebb到全局伙伴；单聊、聊天模式、冲突target、无候选及非法值拒绝。任务模式多@当前群伙伴也明确要求协作；普通聊天招呼不改变策略。显式指定的非负责人伙伴最多3位，计划必须完整覆盖后才创建任何子任务。

保留route目标就绪/clarify阶段，不能直接跳过追问。就绪后由持久的用户约束决定进入plan，模型的direct只是建议，不能覆盖用户决定；原始建议和实际执行分别记录。指定伙伴与策略随同一根任务、补充、等待、恢复保留，补充不能更改策略。模型自动要求delegate却无成员也明确失败，不再静默direct。

复用原计划、物理任务、来源、实际回执、根预算、取消与恢复；不预填模型计划或实际回执，不重放旧失败。它保证派单方式和指定伙伴覆盖，不保证任意自然语言依赖关系都会被模型正确理解；#171仍检查真实两份collect、无依赖、引用、审阅及退出。

相对于跳过路由的方案，保留了歧义追问和原权限边界；相对于只增强提示，可信策略在父调度器执行，不依赖模型遵从。验证契约v19通过真实生产action显式选协作，与v17/v18各自失败记录分开，不合并或替换分数。接口见[AGENT_DEBUG](../AGENT_DEBUG.md)。
