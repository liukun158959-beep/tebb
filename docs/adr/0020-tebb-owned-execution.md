# 0020：事项负责人、tebb 委派与通用自动化

状态：已接受，2026-10-28，用户 Q1–Q7；对应 #145、#146、#147。

## 问题

事项只关联历史 run，不能表达谁负责或明确发起执行。tebb 原先仅在群聊生成委派，普通私聊不能统一操作产品。自动化只有固定复盘及资讯动作。

## 决策

- 负责人由事项拥有，执行由 Collaboration 拥有，业务状态由用户推进。`WorkExecutionService` 只负责跨域准入及同数据库原子提交，不另建队列或修改事项状态。共享公开 `create_execution` / `submit_execution`，历史 links 保留。
- tebb 私聊、事项及通用自动化使用同一协作队列，按需分给自身或职责角色，最多一层。最终 tebb 任务依赖所有子任务，继承项目快照及成果；取消使用原父子传播链。直接找角色入口保留。
- 产品写操作通过 `worker_rpc` 的现有 token 认证连接回到父后台，`tebb_operations` 核对活跃 tebb 身份，再调用 SchedulingService、LocalCalendarService、AutomationService。读写权限及业务回执属于相应服务，工具不另外维护一套日程或自动化状态。
- 通用自动化保存 goal、项目及角色；每轮执行快照和 submission_key 绑定协作根 run，后续只观察此 run。退出、崩溃或保存回执不明时封存未知结果，人工核对只重新接上原执行，不自动重发外部副作用。
- 角色 ID、模型、自定义名字、私有记忆及历史保持，默认名称做版本迁移并备份。目录读取、编辑和终端仍受本轮项目授权约束；Skill 和 MCP 不授予额外目录权限。

## 影响和验证

继续复用工作区 SQLite、任务管理器、认证 WebSocket 及既有取消/恢复。没有 GUI 业务依赖、第二套模型工具循环或新的定时基础设施。增加少量职责明确的编排适配模块，而不是向 App 增加业务代码。

验证入口见 [当前功能与调试](../TEBB_EVOLUTION.md)；测试隔离数据和模型/飞书边界，不对真实飞书做自动测试写入。任意模型的判断质量和第三方 MCP 可用性须在实际配置下另验，不以模拟通过宣称真实执行已验收。
