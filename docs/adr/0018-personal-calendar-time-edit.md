# 周时间编辑复用日程服务，并按事件保留未确认回执

状态：已采纳，2026-10-22；需求和交互边界见 [周日程设计](../SCHEDULE_WEEK_DESIGN.md)，实现单 #138，阶段总单 #123。

周时间轴扩展现有 SchedulingService，沿用 SQLite 工作区事务、日历写资源和认证 RPC；不建立独立日程数据库或新的任务生命周期。CalendarAdapter 从完整详情及显式分页参与人名单派生可编辑资格，和此前仅表示“可关联”的 eligible 分开。只对当前主日历本人组织、权限和完整名单已确认的普通同日个人日程改起止。

创建的幂等键不能套用于 PATCH：现有飞书接口没有条件版本或修改幂等键。改期先持久登记编号，再重新读身份、资格和原时间；原值变化则不发送。PATCH 仅包含起止和 need_notification=false，保留原事件身份及其他字段。远端确认、再次读回、缓存/关联/下一次安排提交分别记录；超时不重发、不作反向 PATCH。前置核对缩小冲突窗口，但不承诺飞书侧原子防覆盖。

资源预留从事件扩展到其关联事项，执行和失败收尾期间拒绝冲突；网络不持数据库、宿主或 WRITES。未确认后只阻止该事件再次改期和关联变更，普通事项编辑继续。明确核对需要持有原事件预留并再次读取当前值；只把观察结果与原编号封存到本地，不把读到旧值当作原请求未执行。不存在的原编号也封存，以阻止迟到的原请求。已删除/不存在与不可访问/读取失败分别处理。

前端采用同一版本族的 FullCalendar 6.1.22，复用其时间网格、重叠和指针手势，配 luxon3 显式北京时间；按需加载，保留原单日侧栏。ScheduleWeekController 处理每个事件的未确认标记和乱序读取，组件只管理日期、表单、键盘及指针预览。手势松手只提交一次，Escape 用日历拖动期间的文档键盘监听补齐焦点在根节点外的情况；表单保存和键盘操作走相同时间校验、服务预检及回执。

验证使用假飞书、隔离数据、无 GUI 后台、认证 WebSocket 和真实浏览器指针，实际 CLI 参数由适配器协议测试约束。没有对真实飞书写入或发出测试通知；打包发布另行授权。卡片拖入新建、多日历、多人会议、全天/重复/跨日编辑不属于本批。
