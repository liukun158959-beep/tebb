# 笔记基础操作共享服务与短时存储保护

load_notebook、new_notebook、save_notebook_note、delete_notebook_note 由无 GUI 的 NotebookService 提供，Bridge 直接调用，App 保留薄兼容方法；旧桌面此前没有笔记页面，本批不新增 UI 或虚构刷新回调。问答、汇总、导出及文件操作生命周期暂留宿主，HeadlessApp 整体继承后续继续拆分。正常 RPC 参数、回执及 JSON 数据结构保持兼容；新建每次分配新 ID，重复保存仍生成新笔记，不改变普通会话选择。

用户选择只读加载不等待模型，三项写入在共享助手或宿主忙碌时立即拒绝，而不是等模型结束后执行。服务通过普通会话服务已有的选择锁短暂预留共享助手忙碌状态，宿主只在准入时非阻塞取得 turn_lock，旧桌面同时检查宠物收尾状态；读操作不预留助手，不因独立任务运行而拒绝。笔记存储采用独立 ResourceLock，所有既有读改写共用它，复用临时文件原子替换；问答模型等待、飞书请求和文件打开不持有此锁。Windows 锁文件初始化必须在获得 OS 字节锁后进行，见 #128。

删除沿用先清理该笔记生成文件、再删除笔记记录的顺序，保留问答历史、其他笔记和来源文档。跨文件操作不是事务：附件清理失败保留记录并报告 partial、已确认删除及失败文件；记录保存异常报告 unconfirmed 与目标 ID，已清理文件不恢复；记录已保存但聚合页读取失败报告 committed，禁止将其误说为没有保存或建议盲重试。知识库读取失败仍明确失败，不静默隐藏来源错误。重复 ID 的异常目标拒绝修改，避免误删多条记录。见 #127。
