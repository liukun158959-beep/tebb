# 日程事实归飞书，事项关联与操作回执由独立服务管理

事项需要安排实际工作时间，并保持业务进度、截止日期和 AI 执行各自独立。一事项可多次安排，一个飞书事件只能归属一事项；解除关系不能删除远端。采用 SchedulingService 连接事项与主日历，纯规则集中于 schedule_domain，CLI 协议集中于 CalendarAdapter，绝对时间校验复用 calendar_time。后台与旧桌面仅组装服务，Bridge 保留认证 RPC 适配；React 侧栏与控制器拥有表单、日期、焦点及断连核对（#136）。

关联及操作阶段使用现有工作区 SQLite 的短事务，复用 WorkBoardService 的公开事务与按事项资源预留。外部网络不可包含在数据库、宿主或全局写锁内；创建同时复用今日看板日历操作资源，冲突立即拒绝。同一事项编辑、移动、归档及安排在操作执行至失败清理期间互斥，其余事项、AI 和读取继续。结果未确认后释放执行预留，仅阻止再次新建。

远端创建无法和本地提交成为同一事务。先确认操作编号落盘，再记录即将发起的阶段，以稳定幂等键调用一次远端，保存已知事件身份，最后原子登记关系和完成回执。超时不自动重发，也不删除已创建事件作补偿。明确核对可以关联已知日程或确认没有有效日程并结束原操作；已知事件仍存在时禁止声明不存在。连接丢失且编号未登记的情况也须明确核对，先在事项预留内封存原编号，阻止迟到请求。不是通过“未查到回执”等同“没有执行”获得重试许可。

飞书是时间事实来源，本地快照仅用于展示。日期查询与关联核对有版本，避免旧响应覆盖新查询或刚确认的事件；超过 5 分钟的快照标记未核对。主日历身份变化不自动换绑，已删除、缺失、不可访问和读取失败区分展示。普通单次定时类型以完整身份和明确类型核对，其他类型先只读；当前首批只支持北京时间日期侧栏，周时间轴和远端拖动改期继续留待后续。接口及恢复细节见 [功能文档](../WORK_BOARD.md)。
