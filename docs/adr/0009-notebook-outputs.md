# 笔记导出及生成文件操作的服务边界与失败回执

五个导出、打开、定位和文件删除 RPC 直接使用 NotebookService，复用基础笔记操作的短时准入与共享忙碌预留，系统动作注入 NotebookPlatform。宿主不再持有这些操作的业务实现；旧桌面的 App 仅保留兼容调用，不新增页面。五项操作忙碌即拒绝，网络和系统等待不持宿主锁、笔记锁或全局写锁，让读取和独立后台任务继续。见 #129。

文件生成/清理、登记、聚合页刷新及系统打开不是事务；回执保留 path/url、阶段及 steps，不以失败推断未发生写入或已回滚。Markdown 保留同名覆盖及旧文件清理；飞书每次新建文档，没有幂等键，超时或异常响应按创建未确认处理，不自动重试。生成成功且登记、刷新完成后自动请求系统打开；启动请求成功不能证明外部应用已显示文档。读取失败时不继续打开，回执保留可核对的路径。单文件删除只清理该文件及其登记，文件已缺失则清理失效登记，保留笔记、问答和来源。前端“打开”的侧栏预览流程仍独立于系统打开 RPC。
