# 项目环境与常驻服务独立于模型任务存活

状态：采用并实现，关联 #190/#191。原有命令以短时隔离和任务收尾回收为目标，不能表达“助手完成配置后，用户继续访问项目”。项目环境拥有持久代码/依赖及官方沙箱身份，项目服务拥有启动、健康检查、预览与停止事实；TaskManager继续拥有一次操作的排队、执行、取消与日志，Collaboration继续拥有用户目标和模型/伙伴流程。

新项目环境复用官方Docker Sandboxes，采用固定digest的官方预发布v3 shell，不声明宿主工作区、SSH或模型凭据转发；实际前台exec会话由项目管理器持有Web进程。官方无会话才idle-stop的契约允许服务独立于模型任务运行，本机构建器未就绪时也可使用已发布workload。官方前台链已通过PoC，公开仓库运行的产品通道采用该SDK；原离线终端保留，不自动迁移旧磁盘或授权。网络授权针对单环境，实际权限仍受官方组织/全局/deny规则合并影响，不能将kit列出的域名冒充唯一允许范围。现有目录授权、历史终端记录和既有环境保留其身份。网络、模型和CLI等待均不持数据库事务，不新建Agent循环或任务队列。

已就绪服务交由项目持续管理，模型任务结束不自动停止它；取消尚在准备的操作须停止该操作尚未就绪的服务，不影响此前已就绪项目。用户显式停止及应用正常退出停止所属运行环境，保留磁盘供后续启动；异常退出后先按原沙箱身份、操作回执及实际健康状态核对，不自动重建、重启或重放。创建、状态、日志、预览和停止均提供认证调试入口及任务/调用关联。采用这项边界需要额外持久回执和恢复观察，换取服务不会被模型进程收尾误杀，也不会把命令退出误报为可预览。

操作回执丢失时保留原候选名；只有明确归属验证才能绑定未知UUID，已知同名换ID一律拒绝。只读失败与配置失败分开：已结束的文件读取错误不应停止VM。项目能力沿用已有编码任务的12轮/600秒默认，显式用户时间设置优先；可信工具可声明有界等待，总时限仍优先。具体接口、退出未确认及兼容边界见[项目运行](../PROJECT_RUNTIME.md)。
