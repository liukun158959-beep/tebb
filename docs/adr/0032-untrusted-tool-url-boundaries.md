# 非可信工具文本的 URL 边界

#208 沿已授权的明确缺陷修复推进。#205/#207 第二个独立真实 Python 样本已启动原教程并取得 `source_integrity.unchanged=true`，但原 Flask 日志转 JSON 后，候选 `http://172.17.0.57:5000\\n\\u001b[33mPress` 被 URL 提取连在一起；后处理抛 `Invalid IPv6 URL`，真实回执未能返回模型。任务失败，未完成明确要求的模型停止步骤；原始失败与439022.51ms、13调用、148333/6007完整用量保留，费用未知。

复用 web_sources 的语法与来源边界：候选在控制字符和反斜线处结束，保留合法 IPv6 的配对方括号；无效候选、本体来源和请求别名不进入来源目录或正文计数。HTML 中畸形链接也不能使已读正文整体失败。语法有效不授予网络权限或来源可信度，实际网页读取仍沿用公开地址、DNS、端口和重定向限制。

独立审阅只使用有效来源的原始已读片段，不能跨未读间隙拼引句；坏来源不阻断其他有效来源。项目日志保留原文本和原字节，仍是非可信数据，其链接不自动升级为正文证据或源码校验。

实际 JSON 转义边界先有2失败/2错误，再以64项相关回归覆盖工具回执、模型收到的原文、审阅继续、IPv6、畸形地址与来源别名。另为新代码预定一次有限真实项目回归，不覆盖先前超时/失败；最后精确CI验证交付代码。
