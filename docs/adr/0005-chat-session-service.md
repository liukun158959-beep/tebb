# 普通会话与任务收尾共同保护

普通会话的新建、切换、清空和读取原来依赖 App / BoardWorkbench，并混入窗口要求与界面刷新。按用户确认的 5 个入口，ChatSessionService 组合 ConversationService，复用已有历史、摘要和事实接口；会话选择仍存于同一 UserState，Agent 临时上下文通过 ConversationService 清理，不复制状态或存储。Bridge 直接调用服务，旧桌面通过兼容方法及显式刷新回调适配；只读记忆页同批复用快照，事实编辑、单句删除和手动压缩另批处理。

仅检查宿主 running 或任务数据库终态，无法阻止独立 worker 的收尾写回。TaskManager 的公开 session_mutation_guard 在现有条件锁下同时检查排队/执行/取消状态与 active 收尾，并保持检查和修改同一临界区，阻止新提交穿入。当前会话未结束时拒绝新建、切换和清空，不自动取消；其它会话任务继续，读取不受回复限制。旧桌面发送前短暂固定当前选择，忙碌状态持续至普通回复/每日纸条的 GUI 回调落盘完成，并兼顾 pet.busy。

清空保留当前 ID，先删除派生摘要，再删本会话历史与临时上下文，保留其它会话、长期事实、笔记及任务记录。空会话新建复用 ID；选择保存失败恢复内存 ID，但不声称跨文件回滚。change_state 区分未修改、文件未确认、部分完成及已提交后刷新/上下文清理失败。清空的锁顺序为 WRITES、会话选择锁、任务条件锁；读取只用会话锁。整个 HeadlessApp 仍保留其它 GUI 继承。
