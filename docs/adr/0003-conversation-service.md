# 对话运行服务独立于桌面与 RPC 门面

普通任务原先通过构造 HeadlessApp 继承 App / BoardWorkbench 来复用业务方法，连带加载窗口模块、读取显示器并构造 Bridge。第一批将普通对话、同入口的知识问答、模型生命周期、上下文及用量集中到 ConversationService；worker 直接构造服务，旧桌面和 HeadlessApp 通过显式接口复用。点选校验与请求构造独立为 conversation_input；用户配置的缩放枚举归配置模块，避免配置反向依赖显示器实现。

任务调度、进程取消、超时、权限与对外事件协议留在原有模块。旧桌面仍负责发送前和显示完成时的历史保存，服务提供共享的模型执行步骤；后台 run_chat 则负责本轮历史和元数据，防止双重记录。其他设置、看板、笔记、自动化 RPC 暂保留继承兼容，后续按职责拆分；本次不宣称整个 local_api.server 已无 GUI 依赖。
