# 业务事项独立拥有进度，与项目共享原子存储事务

work_items 集中本地业务事项、版本、归档和伙伴工作记录关联的纯领域规则，WorkBoardService 负责持久化与回执；AI 执行与交付仍归协作服务，时间安排仍归日程模块。四列移动仅修改用户管理的业务状态，不隐式启动、停止或完成任务。客户端控制器按事项串行保存最新移动意图，组件负责拖动、表单和焦点，认证 RPC 只作协议适配（#121）。

事项复用协作 workspace.sqlite3 的事务，项目删除通过事项领域的公开 detach_project 在同一次提交中解除归属，保留内容与原项目名。选择共享持久事务而非独立 JSON/数据库和双写补偿；事项规则与接口保持独立，协作普通快照不包含卡片。项目服务依赖事项领域接口，看板持久服务依赖工作区事务和事项领域，两者不互相导入。抽出不构造任务管理器的工作区初始化入口，读取和保存卡片不启动后台执行队列；不为看板复制认证、模型忙碌或任务基础设施。

每次修改校验事项版本，并在同一事务保存唯一请求编号、指纹与回执。已确认、提交未确认与刷新失败分别报告；相同编号及内容可手动去重核对，断连不自动重放写入。独立事项并行，同一事项连续移动保留最新意图；版本冲突或结果不明时停止该事项后续写入，先读取核对。完整边界、接口与后续日程顺序见 [业务看板](../WORK_BOARD.md)。
