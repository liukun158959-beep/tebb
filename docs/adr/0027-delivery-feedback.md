# 将交付反馈与执行状态分开

#169的基线出现真实来源与正确JSON内容却未交付正确格式，以及未知SDK结果仅因正文结束而落为成功。决定由产品反馈模块复用来源、资产和真实回执分别检查，在普通worker和伙伴收尾接入；Atlas继续负责通用执行及模型协议，固定提交不变。

确定性证据、模型判断和交付声明标明不同依据。独立审阅无工具且原句按实际片段核对；不能把已读正文等同于蕴含结论，也不宣传自动证明所有目标。结构化JSON作为完整数据文档处理，引用编译不改schema，默认Markdown不能覆盖用户格式。

修订合并为一次、保留成功产物；审阅和修订共用原预算和任务期限。修订阶段在调度前拒绝写入/命令，只允许授权只读及有额度的图表修正。未知写入必须核对原operation，不重发；新补充使旧核验失效。代价是未取得充分证据或额度时返回待核验/部分成果，而不是扩大权限、隐式增加调用或编造完成。

详见[交付反馈](../FEEDBACK.md)。#170继续硬预算，#203继续未知沙箱归档/准入恢复，不揉入本单。

真实v11暴露审阅协议兼容和纠错归属问题。v12允许完整候选JSON按数据等价核对，外部引句仍逐字匹配；单一reason别名兼容、材料层级始终由后端绑定。审阅器协议/引句错误使用同一次修订额度修正评审，不消耗一轮候选重写后才发现额度不足；最多两次审阅、原任务总调用与期限保持约束。规则核对结果作为既有依据输入，模型仍只辅助判断未核对语义。

实际v12子任务算出正确JSON仍因缺少内部提交调用失败，且子任务deliver误用根目标。v13由后台统一接收最终候选，内部声明为可选但明确缺口仍阻塞；用真实parent_run区分当前职责与根汇总，整体约束和分派证明另列。评审条件指向候选满足性，规则引用只复用其真实核对范围，不能代替正文语义。不存在额外Agent或隐式外部成功回执。

v13实测进一步确认：子任务“你必须只返回JSON”的独立指令未被确定性解析，导致传给审阅器的verified_checks为空；这不是单纯模型忘记编号。v14补齐明确指令前缀，并只在唯一同类型真实规则存在时归一省略编号。以原响应重新计算新规则的零调用复核不回填旧Task或分数，模型原理由与系统待核验原因分别保存。
