## 1. 问题

当博士坐在桌前时，有两类雇工：

1. **今日安排**：用一两眼或一句问知道飞书上该盯哪件，好把注意力放回工作。
2. **长时间任务**：有些事要盯半小时（明日方舟日常）。应对桌宠说一句、点看板、或右击选项卡片，由 MAA **一键长草**。桌宠只负责入口和进度，不占死对话轮。游戏窗已在才托管；桌宠不代开启动器或 `Arknights.exe`（启动器那一下必弹 UAC）。没窗立刻失败，人自己去启动器点开始。

方舟侧已经能清日常。接着要问「今天刷什么」时，缺的是**这号仓库是真的**。现在的凑合：手填 json、截图猜图标、或每晚点一次 MAA 小工具。新产品必须比「再点一次识别」更少打扰：跟已经在跑的清日常走。

挂了或清日常失败时，现在的凑合是自己翻 `desk_companion.log`、MAA `gui.log` / `asst.log` 或终端。看板要有一个**不抢主路径**的入口：有问题标红，点开看原文，或跟凯尔希说「看看日志 / 仓库怎么挂的」——分析必须基于工具读到的出错段（桌宠日志 + MAA 任务出错段），不许编。扫仓空结果不当今天已同步。重试由清日常线程按规则再跑一次更新数据，不由模型看着日志决定。

更远的「按号定制养成 / 抽卡」现在不雇。没有账号状态，强度再熟也是编。

- Given 用户只是打开看板日志或问「看看日志」，When 对话结束，Then 没有新的 `LinkStart`。

## 6. 最危险假设

1. 气泡勾选修完后，只勾唤醒+基建+信用再清日常，队列里肉鸽为 false。验证：`gui.new.json`。
2. 写完配置再计划任务拉起，会跑「更新数据」。验证：桌宠清日常后 `DepotData.json` 的 `syncTime` 是否为今天且 `data` 非空（当日已手点过则 Daily 可能跳过 OCR，日期仍是今天、有货算过；空 `data` 不算过）。
3. 日志标红过宽会导致入口永远红。验证：只有今日 CRASH / WATCHDOG / 清日常失败 / MAA 任务出错才红，启动成功的普通 `log()` 和远控轮询不红。
4. Agent 分析日志会编造。验证：工具没读到出错段时不准编原因；有 MAA `仓库识别` 时不准说成网络。
5. 同趟再试会变成整段重跑或留下 EveryTime。验证：重试队列只有 UserDataUpdate；结束后间隔回到 Daily。
6. 把「懂游戏」当成下一步会膨胀成百科。验证：仓能查龙门币、代理卡缺键失败。
7. 计划任务能去掉每次 UAC：**已否**（代拉开启动器仍弹）。V45 改为不代开 exe。验证：有窗时清日常零新 UAC；仅启动器或两边都不在时立刻失败，不弹启动器 UAC。
8. 看板对话工作台会做成插件市场或第二套勾选。验证：chips 只指向已有 skill/工具/仓/方舟动作；清日常仍是同一份 `selected`。新对话不删 `chat.jsonl`。
9. 自动化任务会做成任意命令或关机补跑。验证：动作只有三个；错过只记 `missed` 不执行；定时写入不能 `+create`。

## 8. 竞品对照

观赏/整蛊雇的是屏幕上有东西动。OpenPets 雇的是插件平台。通用桌面 Agent 雇的是一箱子工具。攻略站雇的是「游戏知识」。我们雇 Atlas 当入口：**飞书管日历待办，MAA 管长草，账本管这号有什么**。知识表按需接入，不先做百科。工具按模块注册，不先做市场。两件雇工都要能离开对话轮还活着。
