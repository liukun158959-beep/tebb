# 任务预算

#170统一采用推荐范围：主任务、分工、澄清恢复、审阅和修订共享预算；实际模型请求尝试、真实工具执行、输入/输出token及执行时间分开记录。普通任务和协作/工作流等既有任务复用原生命周期、取消和部分成果，不建立新Agent或队列。

## 已采用的决策

1. 调度器创建/继承可信根预算，物理task ID、阶段或重试不重置；成功后的新问题建立新预算。跨任务管理器共用数据根下同一账本，用户等待补充期间暂停执行时间。
2. 预算在实际ExecutionLLM发送和真实工具execute之前原子核对。插件/事件不负责准入；所有未结算请求保守占用额度，缺usage不退为零。
3. 默认档位由任务调度目的确定；简单8请求/12工具/64K输入/16K输出/180秒，研究16/24/192K/48K/360秒，编码24/40/384K/96K/600秒，图表12/20/128K/32K/300秒，澄清6/4/48K/12K/180秒。具体原有用户硬期限仍约束；分工不自行扩大根额度。
4. 根交付保留2次模型请求及4096输出token。新的实际正文区间、文件/产物版本或已确认操作推进才可支持一次不超过25%的扩展；重复状态、文本长度和unknown不算进展。连续无实际进展停止新工作，保留已取得材料。
5. 精确输入准入仅在绑定真实分词时执行；其他情况展示事后已知用量和未知调用。输出上限参数按确切模型/路由配置与验证；容量中的output_reserve不作为生成参数。价格和费用缺失不是零；金额硬上限不属于本项。
6. 主任务、协作整链、任务监控和调用详情读取同一预算投影，显示限额/实际消耗/保守占用/剩余/模式/扩展依据/停止原因。既有事件与阶段统计留作过程解释。

## 验证计划

先原子竞争、崩溃未结算、父子/继续、暂停、收尾、无进展和已知/未知token的确定性反例；再真实本地任务/RPC/界面与完整CI。真实模型比较固定题目和模型，预算策略分别报告全部成功、虚假成功、用量完整性、费用及尾延迟，不用提高max_steps替代坏工具修复。

2026-10-31实施前两个有限原生探针确认当前mimo-v2.6-flash路由的max_completion_tokens=64/128分别返回64/128 completion_tokens及length；计数包含返回的reasoning部分。仅证明该路由与参数，窗口/分词未声明，其他模型不能照搬。探针原记录与临时凭据清理保存在output/budget-170-cap-probe-v1。

## 实现与调试接口

账本位于数据目录的`memory/task_budgets.sqlite3`，由TaskManager登记可信成员；协作整链、澄清选项、工作流单步/继续和同步旧入口继承或建立同一目标的作用域。SDK发送和实际工具入口准入，不用插件异常或事件计数承担权限边界。已存在但未计量的旧阶段明确标为未知，读历史执行不创建虚假的零消耗。

`list_agent_tasks/get_agent_task`、协作run和`get_debug_call`提供`task_budget`投影，含limits、已回报token、未结算保守占用、未知调用数、剩余、收尾、实际模式、扩展依据与停止原因。任务监控、整链与调用详情共用组件。工具单位为注册工具执行尝试、工作流节点及现有资讯/归档阶段，不是底层HTTP请求次数；SDK调用前已准入而未获回执的尝试也不退额度。

`verify_model_output_limit(model_id,parameter,request_id)`复用现有认证RPC和任务进程，返回稳定task_id；相同编号核对同一任务，断连不重采样。parameter只允许max_completion_tokens/max_tokens。`load_model_output_limit(model_id)`只返脱敏验证状态；生成绑定保存在`memory/model_generation.sqlite3`，与模型/路由匹配，容量output_reserve不充当生成参数。配置面板只在明确点击时发送两次短请求，支持停止；失败的同路由同参数验证停用，观察到服务违反上限时阻止后续发送直至重新验证。精确窗口余量还会限制已绑定生成参数。

## 当前证据

- 原子竞争、未知usage/中断占用、继承/继续、用户等待、收尾、无进展、有限扩展及SDK发送边界等反例通过；小整数扩展向下取整，始终至多25%。重复的已读区间、文件版本及已确认动作不作为新进展。
- 真实RPC/任务进程/Atlas模拟SSE完整链通过；三次原始请求上限为64、128、4096，重复请求编号只生成一个探针任务。前两轮调试脚本的RPC封装/模拟匹配错误保留，未混入真实模型分数。
- 当前真实模型经认证RPC两次请求，分别返回length及64/128输出token，共192输出、38输入；相同request_id没有额外调用。临时凭据删除，后端与观测worker退出。
- 独立业务极小预算反例仅1次真实请求、64输出token，任务failed、目标未完成；作为边界通过，不能计为业务成功。首次脚本遗漏存储初始化在0次模型调用前失败，原记录保留。
- 固定同模型4题各一次：旧策略14次调用、25141/6825输入/输出token；新策略11次、19999/5496，均用量完整，费用未知。最大单案耗时分别200113.01/130691.10ms。小样本且有本机回归并行，不估P95/P99或归因普遍改善。
- 原v14新策略3成功/1 false_success，#206修复题目所需章节覆盖判定后，以原始任务与快照零新增模型调用复判；两组均4成功/0 false_success。原始报告及SHA保留，不覆盖原分。

原证据：`output/budget-170-rpc/`、`output/budget-170-compare/`（位于工作区仓库旁）；模拟、真实模型、零调用复判与完整CI分别记录。最终精确提交CI通过后才关闭#170；不重发冻结的0.4.1。
