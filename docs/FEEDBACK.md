# 交付反馈与有限修订

#169把技术执行结束与用户目标的验收分开。来源链接匹配、正文已读、结论支持、数值口径、命令退出、验证覆盖、产物及输出契约分别记录。没有检查的项目保持未知；模型说complete=true只是声明。

## 规则、回执与模型判断

产品复用真实来源目录、正文区间、图表资产、工具回执、TaskManager和调用追踪，不另建Agent或网络执行器。普通任务worker和伙伴共用确定性反馈；有工具能力、真实材料/操作或最终综合交付的伙伴任务另做有界独立审阅。纯输入计算等没有外部执行需求的路径不强加另一套代理。

- 明确JSON契约检查完整文档、字段与类型，拒绝额外正文、重复键、NaN和Infinity。支持常见中英文独立JSON指令；更复杂自然语言格式不猜测，调用方可声明output_contract。后来的明确格式要求覆盖此前推断，可信固定schema仍须满足。
- JSON引用只转换数据字符串，保留字段和类型，不追加Markdown；code/command/script/example等明确代码字段保留。普通文中的代码示例仍不作为引用。结构化答案未要求引用时，不为凑来源擅加字段。
- URL核对只证明来自实际工具记录，读取节选不升级为全文。独立审阅用当前目标、候选答复、实际取得的片段、工具及前序任务交接；不能联网或执行工具。外部引句必须逐字匹配某个实际片段，不能跨未读间隙拼接；完整候选JSON可按全部字段、值和类型等价核对，仅忽略键顺序、空白与转义写法，不用于来源正文或局部引句；snippet、候选自己的话和目标文字不能冒充外部正文。
- 语义和数值口径由模型辅助判读，标记model_assessment。数值比较要求双方原句、年度/单位/指标一致性；它不是形式化证明。实际格式、资产、退出码和已读范围继续用独立规则核对，不用模型自评分代替。
- 命令退出0单独记录，不证明覆盖或产物。声明产物可绑定原调用，或绑定明确环境/根目录和路径的实际文件读取及内容摘要；同路径来自多个环境时不猜归属。测试范围没有独立回执就未知，不能从“npm test退出0”自动宣称完整覆盖。

报告completion为checked（列明条件已核对）、assessed（含模型判断）、unverified或incomplete；scope明确不证明全部自然语言目标。伙伴界面展示各项依据与未知原操作编号。任务状态仍表示执行生命周期，不能单独充当验收结论。

## 一次修订与未知操作

各项反馈合并为一次定向修订；已有有效正文、图表、来源和原操作编号保留。修订只允许已授权只读工具及原额度内的图表修正，写入、创建、发送和命令在调度前拦截，不依赖提示词自律。原任务执行阶段仍按原授权工作。

若修订生成中途报错，恢复此前保留的候选稿供审阅，不补造result或成功状态；新目标已使旧稿失效时不会将旧稿恢复为当前成果。原候选及核验事件仍可追踪。

独立审阅每次只调用一次模型；共同的一次修订额度用于改正候选缺陷，或修正审阅器自己的协议/错误引句，最多两次审阅。后一种保持候选不变，不让写作模型重写正确答案。规则已通过的格式、URL和读取范围传给审阅器，减少重复判断；正文证明要求不放宽。它们与正文调用共用原调用总额、任务总期限和取消控制，均有llm_start/end、usage及HTTP记录，审阅phase为feedback_review。没有剩余额度或审阅不可用就标待核验，不能额外绕过预算或改报成功。金额/输出硬预算由#170继续处理。

真实写入/执行回执仍unknown时保留待核对，不因最终文字改成完成；后续只有同operation的真实新回执才能解除未知，不按名称或另一个成功操作推断。只读查询如实返回unknown可以完成查询本身。修订中不会再次创建。SDK准入释放/归档仍由#203处理。

同一执行循环中，在任何草稿或正式修订之前，未知写入也立即阻止后续写入；改变工具参数、调用编号或一次请求多个调用不能绕过。普通Atlas路径解包公开工具事件的output，伙伴路径使用原RPC结果；日程unconfirmed、事项request_id与不明写入异常保留原身份。查询失败、仍在进行或只说明查询没有改动，都不能解除此前的未知；明确not_changed的原始前置失败不会被误判为已发送。只读核对和已有额度内的图表仍可继续。

审阅期间收到补充要求时，原核验失效并重新处理，不能把旧稿的批准套到新目标。前序交接只证明调度器中确有该任务与回答，不自动证明回答里声称的外部操作。

## 调试接口

纯规则入口是feedback.check_output、check_receipts和report；delivery_feedback.assess复用真实引用及图表检查。feedback_review.review接受调用方预算控制的call回调，没有工具执行权。回执由业务服务提供，不能将模型自己写的JSON当作实际产物证明。

内部认证任务通道支持workflow=collaboration、kind=feedback_review，参数review_goal、review_draft、source_evidence、review_receipts、acceptance及budget。这是审阅候选的任务；返回incomplete表示发现原候选缺陷，审阅任务自身可以正常结束。提供材料的出处由调用方负责，不能把合成输入冒充新抓取网页。

声明契约示例：output_contract={"format":"json","schema":{"type":"object","properties":{"total":{"type":"integer"}},"required":["total"],"additionalProperties":false}}。复用已固定的jsonschema，不下载外部$ref。

反馈通过feedback_check事件及伙伴feedback_check字段读取；HTTP调用ID、source ID、原operation及项目回执仍走原调试入口。普通worker核验未通过会保留回答并报未完成，不在结束后额外发起无预算的工具循环。

## 验证范围

统一评测v11/v12保留原26案，追加四类只读审阅反例，共30案。feedback_unsupported、feedback_partial_read、feedback_incomparable使用明确标记的合成材料；feedback_missing_artifact使用受控宿主退出探针和真实缺失文件检查，不能称为Docker项目运行验证。研究与真实分工案例沿用原任务，检查实际读取/原子任务和最终格式。

模拟链路、真实模型固定小批次、完整CI和旧v8/v10失败分别报告，不回填旧分。调用实际记录和原句/资产/生命周期验证共同构成验收依据，不把一次模型自评当作正确性基线。当前仍在验证，未先报#169完成。

评审协议v2仅兼容单独出现的status_reason别名；reason与别名同时出现仍拒绝。模型重复给出的evidence.level被忽略并按实际材料目录重新绑定；额外字段、未知枚举与错误类型仍拒绝。实际工具回执、checkout提交和service_preview启动时HTTP可证明各自观察，不升级为研究正文或全部目标成功。
