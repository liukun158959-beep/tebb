## 一份图稿，有限修正

- 工具 Schema 与服务共享字段边界，复用已在运行时提供的 jsonschema。首次预检一次列出可定位的问题，如 `/calification`、`/edge_labels` 的需要/实际数量，以及 `/flow_style` 的环节点；拼写建议、布局候选只是建议，不自动丢字段、补条件、删回边或降级来源。
- 预检返回 `draft_id`、`issues[{path,message,hint?}]`、`repairs_remaining` 与 `repairable`；修正同图须带回编号。旧调用未带编号时按本任务链的图类型与标题匹配。最多8份图稿，每图首次提交后最多两轮定向修正，仍受现有模型调用与总时限限制。
- 图稿回执与既有4次实际渲染预算共用持久登记和短时存储保护；同图使用单独非阻塞资源保护。参数失败不计实际渲染；真正渲染失败仍计数。成功图以数据及来源指纹复用，重启后仍可查，重复读取不重新构建。
- 实际渲染额度耗尽返回独立的预算阶段且不可修正，不误报成保存未确认，也不提示模型反复修改参数以获取额度。
- 渲染前保存原资产编号；渲染/登记中断时先核对该编号。完整登记且哈希、任务归属与原图稿吻合才复用；无法确认不盲目重建。结果保存阶段失败保留实际阶段与已确认格式。
- 图表/报告仍沿用真实资产与来源检查：明确要求图表却没有真实图时不能完整完成。来源与资产校验不能自动证明每项用户语义目标都已满足，模型交付声明和用户审阅仍必要。

数值、时间线要求实际已读正文；流程示意可无来源或引用实际摘要并明确未读正文，不能把示意包装成评测排名。正文、数据及错误保留：执行过程可展开图稿、预检路径、修正历史、构建结果与编号；图表助手身份、主/子任务及整链调用数复用原任务树。图稿仍在构建时任务结束，界面标为结果未确认。明确要求图表的任务在修正时清空旧展示后若失败或超时，恢复此前已收到的非空正文，任务仍为失败/超时，不写成成功成果。
