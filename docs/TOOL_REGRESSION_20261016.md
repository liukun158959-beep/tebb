# Agent 工具回归与交互修复（2026-10-16）

## 交付

工作台从覆盖层改为实际占据空间的分栏，窄窗口上下排列；输入区可以换行，发送按钮不再位于工作台下面。任务详情在窄聊天区停靠底部。对话记录与伙伴目录分成标签：会话负责续聊，伙伴负责配置与发起新对话。宠物右键移除重复的打开/关闭聊天项，单击宠物仍切换浮窗。

笔记围绕资料与成果衔接：成功完成的聊天回答可收藏，按实际任务去重；任务登记消息和未完成结果不能收藏。收藏明确标记 AI 生成、未经额外来源核验，引用指向真实聊天记录，不冒充外部研究证据。笔记可生成完整只读附件快照，加入当前伙伴会话草稿，不自动发送；原始长文与引用保留，不受输入框4000字限制。

## 超时发现与处理

1. 旧编码伙伴把拥有编辑能力等同于所有请求都必须打开目录；无目录代码示例已修复（#98）。
2. 普通代码回答曾要求包装成JSON，模型误返回Markdown后又重新生成一次。现在普通回答直接接收Markdown，真正执行用函数请求登记后台任务；保留旧JSON兼容与受限格式校验，不靠猜测意图执行工具。
3. 伙伴任务写死90秒调用时限，监控台保存的等待设置没有应用。现按共享设置应用于之后排入执行队列的任务，已有任务保持原值；没有自定义值时保留原默认值。
4. WSL命令允许最多120秒，但原监督器可能先按90秒等待上限结束。现在命令按自身上限加20秒收尾等待，任务总时限仍是硬限制。函数参数流也计为模型进展，不再仅靠正文/推理文字维持等待。
5. 内部路由使用low推理；真实代码执行保留用户配置。GLM工具轮次保留并原样回传本任务内模型推理块，避免丢失工具调用上下文；推理块不作为聊天文字发布。参数依据：[GLM思考模式](https://docs.z.ai/guides/capabilities/thinking-mode)、[GLM-5.3-Flash](https://docs.z.ai/guides/vlm/glm-5.3-flash)。
6. 最近一次用户编码超时已完成TCP约118ms、TLS约45ms以及请求发送，但等待响应头约88.6秒后结束，没有收到首段文字。该次尚未进入任何文件或终端工具；无法从客户端判定中转、上游网络或模型内部原因。超时提示现区分模型等待、工具等待和总时限。此类长尾继续跟踪[#97](https://github.com/liukun158959-beep/tebb/issues/97)，未宣称已消除。

## v0.3.0 发布前补充：GitHub 仓库读取

用户在「开源项目观察」中的失败不是模型直连导致 GitHub 失联。原执行记录里 `github_status` 和 `github_recent` 已成功找到私有 Atlas，但没有沿用登录态读源码的工具；匿名网页路径还受到来源登记限制。另一个研究任务一次提出三次搜索，触发两次搜索额度后整批未执行。

新增 `github_repository` 只读工具，沿用 GitHub CLI 登录，支持仓库发现、目录、README 和分页源码读取；私有仓库限定本人仓库，拒绝凭据路径、链接与子模块。伙伴仍需已有的「扩展只读工具」权限。工具来源纳入引用核验；超预算批次执行剩余许可请求，超出项返回未执行回执，不提高总预算。

真实模型隔离验证：使用原失败任务的模型配置与原网络策略，7 次模型调用，约 75.75 秒，成功自主发现 Atlas，读取 README、目录与 `atlas/core/loop.py`。README SHA 为 `044aecc52aa4d206c2c6fca7f14e2311e4490ce8`，核心文件 SHA 为 `9fd685201b9a504ede728dacd881de3abd9b307a`。没有配置本地项目、克隆仓库或执行终端，也没有改动用户对话。这个样本验证发现与源码读取能力，不代表已完成用户的完整框架对比报告或性能分位数验收。
