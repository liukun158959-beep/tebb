# 工作台关闭与重开

对应#212。工作台是常驻桌宠的主窗口：右上角关闭和Alt+F4只隐藏窗口，保留当前页面、未提交输入和同一个WebView；桌宠菜单“打开主窗口”恢复、显示并聚焦该窗口。“今天的安排”和伙伴跳转继续复用同一窗口。桌宠“退出”仍调用原quit_app及后台正常收尾，不把隐藏当作进程退出。

Rust的main_window模块拥有主窗口关闭监听与恢复；setup在开始后台工作前安装监听。没有加入重建窗口或旧版本适配分支。菜单错误格式由pet-menu拥有，底层已给出恢复建议时不重复追加。

## AI验证

复用实际Tauri事件循环和生产关闭监听，不依赖假Window对象。先按开发指南安装依赖并在client执行pnpm build，再在仓库根执行：

```powershell
python scripts/verify_main_window.py --work E:/temporary/new-window-lifecycle-probe
```

work必须是新的绝对目录。入口通过Cargo及Microsoft链接器为example显式嵌入Common Controls v6清单；example不自动继承主EXE的该清单，不能以缺少TaskDialogIndirect入口点的探针冒充已执行窗口测试。测试使用独立应用标识与该目录下的WebView数据，创建明确标题的原生验证窗口，连续三次调用真实close、核对主窗口仍存在且隐藏，再通过生产show恢复可见，最后正常退出。它不启动Python后台，不调用模型、飞书或读取真实用户配置。result.json记录实际结果，source.json记录实际源码根、文件及EXE摘要；失败保留具体原因，不把轮数结束当成功。该程序验证原生生命周期，不替代完整客户端的后台、页面草稿及桌宠菜单验收。

完整客户端使用独立验证标识和合成数据启动。打开工作台，在编辑框输入未提交文本，关闭主窗，再从同一测试桌宠选择“打开主窗口”，确认原页面与输入仍在；重复关闭/重开，并检查后台PID未变化。“今天的安排”应显示日程；最后从桌宠菜单“退出”，核对原生与后台均结束。仅关闭主窗不能作为退出验收。故障和失败摘要分别保留；冻结0.4.1发布包不因源码修复而改写。
