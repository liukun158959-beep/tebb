# 业务看板与日程联动

业务看板实现对应 [#121](https://github.com/liukun158959-beep/tebb/issues/121)，采用 2026-10-21 确认的“轻盈看板”视觉与全部业务规则。已接入实际客户端、独立服务和本地认证 RPC；[#124](https://github.com/liukun158959-beep/tebb/issues/124) 本批仅落实看板所需交互。日程联动 [#123](https://github.com/liukun158959-beep/tebb/issues/123) 按下文顺序另批交付。

## 已确认的看板范围

- 卡片代表本地业务事项，可选关联现有项目，无项目事项也可独立保存。项目继续拥有目录、对话及权限；不将飞书待办或 AI 队列改造成业务事项存储。
- 四列为待办、进行中、待验收、已完成，可跨列移动和重新打开。业务进度由用户推进，拖动不自动发起或停止 AI，也不改写真实执行结果或自动完成飞书待办。
- 标题必填；说明、项目、优先级、截止日期（到日）可选。支持项目/关键词筛选，列内按优先级、截止日期、创建顺序稳定排列。
- 首批不包含自由排序、自定义列、子事项和多人分配。界面以已认可原型的卡片、四列和详情设计为基线；保留今日看板和执行任务入口。
- 支持归档/恢复，首批不永久删除；恢复保留原状态、内容和关联，归档不停止 AI。项目移除与事项解除项目关联在同一事务中提交，事项回到未归属列表，显示原项目名；聊天、文件和执行记录保留。
- 一件事项可关联多条现有执行任务页主列表的伙伴工作记录，也可解除。默认同项目优先，允许明确选择其他项目并显示来源；不改变权限、不从卡片直接派发 AI。普通助手、飞书、视频等旧队列暂不关联。委派计划的执行成功与整体交付结果分别显示。
- 同一卡片连续拖动串行保存并合并最新意图，旧回执不覆盖新操作；独立事项可并行。确定失败恢复已确认状态，版本冲突要求刷新；断连或结果不明仅暂停该卡片，保留操作编号并先读取核对，不自动重发。原操作确认后，尚未保存的后续移动由用户重新操作。
- 卡片“移至”菜单和详情状态选择提供等价操作；支持键盘拖动、焦点恢复、抽屉焦点限制和减少动效偏好。样式、认证和页面保活复用现有客户端；拖动复用 `@dnd-kit/core`，布局动效复用现有 framer-motion。

## 职责、存储和接口

`work_items.py` 集中事项校验、版本、归档、执行关联和解除项目归属等领域规则，不依赖存储、宿主或队列；`WorkBoardService` 负责持久事务、请求去重和失败回执，读取项目与伙伴工作记录但不构造任务管理器。事项保存在现有 `memory/collaboration/workspace.sqlite3` 的 `work_items` 中；仅共享事务以便原子解除项目归属，业务卡片不暴露在旧协作快照中。项目服务只调用事项领域公开接口，不反向依赖看板持久服务。`work_receipts` 表持久保存操作编号、请求指纹和提交回执。现有数据按需初始化，不删除或改写旧任务格式。详见 [ADR 0016](adr/0016-business-work-board.md)。

后台与旧桌面组合相同服务，Bridge 提供两个 RPC，沿用 WebSocket Token 和白名单；不占共享模型忙碌状态、不等待模型结束：

| RPC | 输入 | 结果 |
| --- | --- | --- |
| `load_work_board` | 可选 `request_id` | `ok, revision, items, projects, runs, receipt`；只暴露展示所需执行字段 |
| `change_work_item` | `action`，含唯一 `request_id`、`type`，修改还需 `id, version` | 成功返回最新页面和 `receipt`；支持 `create/save/move/archive/link/unlink` |

新建/保存的 `fields`：`title`（1–120 字）、`description`（最多 8000 字）、`project_id`（空串表示未归属）、`priority`（`high/normal/low`，默认中）、`due`（空串或 `YYYY-MM-DD`）。新建默认待办；移动使用 `state: todo/doing/review/done`，归档用 `archived: bool`，关联/解除用公开执行记录 `run_id`。每事项最多 50 条关联，总计最多 20000 件（含归档）。

修改须携带当前 `version`，不匹配时返回 `conflict: true`、`change_state: not_changed`。重复的同编号同内容请求返回原回执，不重复新建；同编号不同内容拒绝。事务提交结果不明为 `unconfirmed`，已确认保存但刷新失败为 `committed`，都保留 `request_id`/已取得的 `receipt`。客户端不自动重发，显式读取仍查不到回执时，允许用户手动重试原编号和原内容以安全核对。失败包含实际 `stage` 和 `error`，不能以传输成功替代业务 `ok`。

## 已确认的日程联动方向

事项截止日期表示最晚完成日，时间安排表示何时开展工作；一件事项可分多段进行。复用飞书日程，通过稳定的事项标识和飞书事件标识建立关联，不另建平行的日程事实来源。

卡片详情中的“安排时间”打开日程侧栏，可以关联已有日程，或填写日期、起止时间/时长；明确确认后才创建飞书日程。卡片显示下一次安排并可定位日程，日程可返回事项。工具栏“日程安排”进入独立周视图，普通个人日程可拖动改期、调整时长；卡片拖到周时间轴新建安排留后续。这些操作不改变事项进度。事项完成后保留关联日程记录。

看板服务拥有业务事项和进度，日程模块拥有时间与远端修改，关联接口连接两者；本地缓存用于展示，不能替代远端修改的确认结果。首批已确认及实现的边界如下。

## 日程联动首批（#136，首批边界）

2026-10-21 用户确认 Q1–Q5 全部推荐规则。#123 为日程阶段总单，首批交付单为 [#136](https://github.com/liukun158959-beep/tebb/issues/136)。

- 当前飞书用户主日历，明确北京时间 UTC+8；侧栏按日期查看与定位，支持跨日普通单次定时日程。新建前明确确认，标题默认取事项标题且可编辑。已有普通单次定时日程可关联；全天、重复或类型不明只读展示。参会人、提醒配置、多日历、远端改期及新增删除入口留后续，旧今日看板保持兼容。
- 一事项多日程，一日程仅关联一事项；换绑前先解除，解除仅移除本地关系。完成/归档保留关联和日程，归档先恢复再新增或调整。
- 先确认操作编号落盘，再创建远端并登记关联。创建、登记及刷新分别回执；已创建但登记失败保留事件 ID 和事实，不删除或重发。超时/断连未确认暂停该事项再新建，先核对飞书，明确关联已有或确认未创建后再操作。失效读取区分已删除、不可访问、读取失败；旧时间未核对时明确标示。
- 安排新建/关联修改期间预留该事项，拒绝编辑、移动、归档及重复安排；保存或失败收尾后释放。结果未确认仅阻止再次新建，其余事项/AI/只读继续；飞书操作资源竞争立即拒绝。长网络等待不持数据库事务、宿主或全局写锁。
- 下一次安排优先正在进行的已核对事件，其次未来开始最早；过去、取消和删除不算。读取失败不误报无安排。日程定位到日期/事件；返回事项揭示普通/归档列表，清除挡住目标的筛选。离开未保存表单先提示保存或放弃。
- 验收包括无 GUI、认证 WebSocket、假飞书的创建/查询/故障/并发及真实 UI 日期选择和双向定位；完整回归和冗余自审后提交，不发布。

### 交互、缓存与恢复

工具栏现进入下述独立周视图；事项详情“安排时间”和卡片时间入口打开同一单日侧栏，定位到关联日程的日期和具体事件。侧栏能新建、关联已有、解除本地关联、定位事项。新建表单明确确认才发送；离开已修改的事项或安排表单时提供保存/明确创建后继续、放弃和继续编辑。日期和起止时间复用既有 DateTimeField；侧栏焦点和日期弹层共用范围，Escape 先收起日期选择，再处理表单。

日程身份由 `calendar_id + event_id` 固定；切换登录后的主日历不自动替换原关联。最多每事项 50 场安排。刷新某事项会核对其全部关联，最多 4 路并行，每次 CLI 请求沿用 20 秒超时；前端同步 RPC 等待 120 秒，超时后后台仍可能继续，不能据此重提写入。只读本地轮询不自动发起远端请求，打开侧栏或明确“读取核对”才读取飞书。已核对快照超过 5 分钟按“上次信息／未核对”显示，不当作可靠的下一次安排；失败保留原时间与错误。日期列表和关联使用请求版本，旧查询不能盖过新核对或确认创建。

新建直接调用原生日程创建，显式不创建视频会议、参会人或提醒，不沿用快捷命令的隐式默认值。只读主日历允许查看；关联仍须重新取得完整普通单次定时日程。归档只读已有安排；原今日看板删除远端日程的行为保持兼容，关联在下次核对时显示失效。

断连前，客户端只在本机保留操作编号、事项、日期和类型，不保存密钥或表单正文；服务端回执是最终依据。重连先按原编号读：已完成则展示事实，未完成则提供明确核对。未查到原编号也不能直接重建；核对飞书后，可明确关联已创建日程或确认没有有效日程。服务在事项预留内封存原编号，使迟到的原请求不能再次执行。已知远端事件须核对它本身，不能悄悄替换为另一场；仍存在时禁止确认“没有有效日程”。

### RPC 与职责

| RPC | 输入 | 结果 |
| --- | --- | --- |
| `load_schedule` | `day: YYYY-MM-DD`；可选 `item_id, refresh=false, request_id` | `ok, day, calendar, events, events_valid, events_error, checked_at, links, items, operations, operation`；`refresh=false` 只读本地，`true` 核对远端；未确认创建列于 `operations` |
| `change_schedule` | `action` 含唯一 `request_id, item_id, version, day, type` | `ok, change_state, stage, request_id, operation`；成功附最新本地页面；不自动重发远端 |

`type=create` 携带 `summary,start,end`，起止必须带时区且结束晚于开始，不创建已经结束的安排。`link/unlink` 携带 `calendar_id,event_id`；`resolve` 携带原 `operation_id`，并明确 `resolution=link` 加事件身份，或 `resolution=absent, confirmed=true`。后者只结束本轮核对，不删除远端日程。归档事项仅可结束无有效日程的核对；新增关联先恢复事项。修改必须使用当前事项版本，重复原编号只返回原事实，不执行第二次创建。

操作阶段 `prepare → remote → association → committed` 持久保存；状态包括 `prepared/calling/remote_created/unconfirmed`（需核对）、`linked/unlinked/resolved_absent`（已确认）、`resolved`（原操作已由核对处理）、`not_started`（确认未开始）。保存回执未确认时不声称回滚；保存成功但页面读取失败返回 `change_state=committed, stage=refresh`。先查询回执和关系，再决定下一步。

`schedule_domain.py` 集中唯一归属、快照与下一次安排等纯规则；SchedulingService 拥有回执、查询顺序及外部生命周期；CalendarAdapter 只负责用户主日历 CLI 协议和事件类型/错误归一。时间校验从原今日看板提取共用，原接口兼容别名保留；不向 App/Bridge 堆业务逻辑，也不改动 Atlas。设计见 [ADR 0017](adr/0017-work-item-scheduling.md)，可复制的离线调用与故障排查见 [事项日程验收](AGENT_DEBUG.md#事项日程联动验收)。

## 周日程与个人时间调整（#138）

独立周工作区按周一至周日展示，北京时间 UTC+8，默认 08:00–20:00，可切换完整 24 小时；时段外或跨日安排有提示和定位。窄窗口显示选中一天并保留七天切换。工具栏、单日侧栏和卡片可互相定位；单日侧栏继续负责新建/关联/解除，未保存表单离开先提示。采用 FullCalendar 6.1.22 与 luxon3 时区插件，打开周视图时才加载。

日程被选中后重新核实当前用户主日历、本人组织者、写权限和完整分页名单。名单为空或只有已核实的本人组织者可编辑；其他人、群、会议室/资源、未知参与项、分页不完整、全天/重复/跨日、已结束或归档事项关联先只读并说明原因。“可关联”不能作为“可修改”的依据。进行中的个人日程可以调整，目标结束必须晚于现在。

正文拖动保持原时长；上下边缘调整起止，15 分钟吸附，缩放最短 15 分钟，已有更短日程保持原时长可移动。松手仅发送一次，Escape、无效位置和时间未变化不发送。键盘聚焦时间块，空格抓取，方向键移动 15 分钟/一天，Shift + 上下调整结束，Alt + 上下调整开始，Enter 保存，Escape 取消；跨周用日期表单。表单沿用既有日期时间组件的 5 分钟选项，不改变其他业务的输入步长。开始结束须在同一北京时间日期，允许跨周或时段外；与已读日程重叠只提示。

写入前再次核对资格和原时间，已变化则显示最新值、要求重新调整。只 PATCH 同一事件的起止和 need_notification=false，不重建、不清空其他字段。确认写入后读回，再提交日/周缓存、关联和下一次安排。执行及失败收尾期间预留事件和关联事项，其他事项、AI 和读取继续；现有共享日历写资源冲突立即拒绝。远端等待不持宿主、数据库或 WRITES。

超时或断连保留编号、原/拟调整时间。重连只读原回执；原请求仍活动时拒绝核对收尾。读到旧值不证明没有执行；明确“以当前已核对状态结束等待”只再读一次并封存本地原编号，不 PATCH。确认缺失/删除可按失效状态结束等待，不把不可访问或读取失败当删除。结果未确认仅阻止该事件改期及关联变更，普通事项修改在收尾后仍可进行。真实飞书没有条件版本，不能承诺和远端同时修改之间原子防覆盖。

| RPC / 动作 | 输入与结果 |
| --- | --- |
| `load_schedule_week` | `day`；可选 `refresh=false, request_id`。按该日所属周读取，返回 `week_start, week_end, events` 及原页面字段；`operations` 列出未确认改期。无远端读取时仅返回缓存与回执。 |
| `inspect_schedule_event` | `calendar_id,event_id`。返回 `ok,event`，派生 `editable,edit_reason,edit_checked_at`；失败保留可取得的旧时间并标实际 `verification`。 |
| `change_schedule / retime` | `request_id,calendar_id,event_id,day,original_start,original_end,start,end`；起止带时区。不要求有关联事项，原编号幂等返回事实且不重放。 |
| `change_schedule / reconcile_time` | 新 `request_id`、原 `operation_id`、日历/事件、`day,original_start,original_end,confirmed=true`；`verification` 默认 confirmed，核对明确 missing/deleted 时须传相同状态；不调用远端写入。 |

改期阶段为 `prepare → preflight → remote → verify → commit/committed`；`prepared/calling/remote_changed/unconfirmed` 需核对，`retimed` 完整完成，`unchanged` 未发送，`not_started` 确认未开始，`observed` 只确认当前观察值。原未知执行的 `execution_result=unconfirmed` 仍保留，不能改写为确定未执行。页面读取失败保留 `change_state` 和操作回执，先按原编号查询，不重发。实现决策见 [ADR 0018](adr/0018-personal-calendar-time-edit.md)，验收见 [AI 调试](AGENT_DEBUG.md#周日程与个人改期验收138)。
