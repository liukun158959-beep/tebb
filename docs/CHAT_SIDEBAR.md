# 伙伴聊天侧栏与新对话草稿

关联 #180。用户已确认项目树、统一紧凑行、唯一新建入口，以及普通新对话首发后入列。v0.4.1 准备在本批优化完成后进行。

## 使用边界

- 顶部“新对话”进入当前窗口的一份新私聊草稿；默认 tebb，从项目对话发起时默认沿用该项目，并在发送前明确展示，可修改。
- 接收伙伴、项目、正文、Skill、附件和模型独立于旧会话。切页、选择已有会话或重复点新对话，会保留并恢复原草稿；换伙伴保留正文和材料。草稿只在当前窗口保留，不新增重启后的草稿恢复承诺。
- 选“新建协作群”复用既有群聊表单和明确创建操作；取消群聊表单后普通草稿仍在，不自动合并已有群聊。
- 项目内外统一小图标、标题字号和行高。会话操作、项目设置、待你处理和伙伴配置继续可用；伙伴目录选择伙伴只进入草稿，配置由独立设置按钮打开。
- 文件夹与历史目录整理位于右上角管理。它们沿用现有项目选择及确认流程；没有新增搜索、置顶或会话归档。
- 旧会话和旧空会话保留，不自动删除。放弃草稿必须明确确认，只清除这份本地未发送内容。

## 首发事务与失败

前端使用固定 dm-加32位hex 标识保存草稿。首次发送通过既有 collaboration_action，在 send 中显式携带 new_chat: {agent_id, project_id}，而非先调用 new_chat 再发送。

后端在原有事务中创建私聊、首条消息、pending 任务与去重回执。项目、伙伴、模型、材料、预算及 sampling 等校验失败全部回滚，不留下空会话。后续 tick 继续复用原任务队列与 submission key。

首发去重编号固定为草稿 ID，完整请求在首次发送时冻结。断连或回执不明不自动重发；原正文和目标保留，用户可核对列表后显式重试原请求。切换会话不会改变原请求的目标或编号；相同编号不同内容仍被后端拒绝。

收到可核对的会话与首条用户消息快照后，前端完成草稿交接；即使原回执丢失也不会再次发送。发送尚未确认时，表单不允许悄悄修改原请求。此时明确放弃只关闭本地草稿，不承诺取消后台可能已经接收的任务。

新草稿不是已有会话：实际请求与伙伴记忆在首发后按真实会话查询；不能把旧会话上下文或工作区显示成新草稿的实际请求。首发任务仍在服务端按目标项目固定权限，不扩大目录/工具授权。浏览器受限入口同样核对所选伙伴本地工具权限。

## AI 调试与验收

无需新增调试端口，复用认证 collaboration_action / load_collaboration。

~~~powershell
$env:PYTHONPATH = "$PWD;E:/path/to/Atlas"
python -m unittest tests.test_conversation_start tests.test_collaboration tests.test_local_api -v
cd client
node --test tests/chat-prototype.test.cjs tests/live-collaboration.test.cjs tests/context-debug.test.cjs
pnpm test
pnpm exec tsc --noEmit
~~~

test_conversation_start 使用隔离存储和假队列，检查原子性、参数失败回滚、跨选择/重启后的去重、ID 冲突和受限浏览器权限；认证 WebSocket 用例验证一条首发仅登记一次，并拒绝错误 token。真实组件验证草稿恢复、项目/伙伴选择、明确放弃、失败保留及快照核对。

真实界面另外核对浅/深主题、窄窗、展开/收起、长标题、唯一新建入口、管理菜单、首发与断连；不向真实模型或飞书发送测试请求。已有会话删除、移动项目的活跃任务保护不变。
