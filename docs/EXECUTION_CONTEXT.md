# 本轮材料与模型容量

#168统一普通对话、伙伴与子伙伴的调用前检查。产品用 `ExecutionLLM` 适配Atlas的公开chat接口；Atlas继续负责通用执行、流式协议和SDK资源管理，固定运行时提交不变。网络调试边界仍记录实际发送请求，不在调试传输层偷偷改材料。

## 材料与职责

伙伴不再默认只选最后20条、每条8000字符；已有手动摘要和覆盖记录继续有效。当前任务职责、阶段与真实授权范围是本轮工作，整体目标保留背景和约束，不要求每位子伙伴再次执行全局分工。历史失败/未知回执保留原编号，历史授权不扩大本轮权限。

来源目录与本轮剩余工具次数只替换worker自己持有的旧消息对象。即使用户文字相同，也不会按字符串匹配删除它。普通对话保留原历史与显式手动摘要，取消固定128K/16K字符估算触发的自动保存摘要；原始历史不会被本轮材料缩减覆盖。

## 容量与计数

容量仅来自与模型ID、模型名和端点匹配的 `model-capacity.json`。没有声明窗口就保持未知，不推测128K；没有绑定匹配的离线fast tokenizer及聊天模板，就明确本地计数不可得。已有分词器支持完整消息和工具定义、文件签名与离线加载，不下载权重或运行自定义模型代码。

本地计数是所绑定模板的实际计算，服务端模板仍可能不同。provider usage是本次发送后的真实回报，不能当作下一次变化请求的精确预估。历史面板的字符估算只描述历史准备量，不冒充完整请求或确定窗口占用率；未知值使用null。

已知窗口和本地计数时，完整消息及工具定义须能放入 `window - output_reserve`。输出预留用于输入准入，不更改API生成参数；输出token/金额硬预算仍由#170处理。未知窗口或计数不触发猜测窗口的有损压缩，也不保证服务端接受任意大输入。文字材料另有2000000 UTF-8字节保护上限，不是token窗口；内联图片等媒体字节不计入此文字上限，仍遵守原工具与服务限制。

## 超出已知输入窗口

复用Atlas的旧工具结果缩减原语，按本地实际计数选择可容纳的摘录长度，每次修改后重算。只处理已登记的可回读只读工具、带稳定来源/日志编号的较早成功正文；工具结果自己声称“成功”不能授予只读资格。最近两轮工具调用的全部结果、视频证据、失败/未知和写入回执、全部系统/用户职责与授权保留。工具调用与响应不拆开，操作编号、来源及状态不裁掉。

摘录附有 `context_excerpt` 和来源/原长度，系统明确说明本轮不再持有完整正文，必要时重新读取。不能放下受保护材料，或整理期间分词器失效时，明确报错且不发送未经核对的请求，不偷偷丢掉目标。自动路径不额外调用模型生成摘要；用户仍可主动整理较早对话，审阅可见摘要，并保留原文以便核对。

## 调试与验收

- 纯业务接口：`desk_companion.execution_context.prepare_request(request, capacity)` 返回实际选用材料和决定；拒绝时 `ContextAdmissionError.report` 保留原因。调试不需要先发送模型请求。

- 切换模型时更新容量身份；观察回调失败不改变原调用结果或自动重试。公开评测隔离复制所选模型的容量/分词绑定，实际凭据仅在临时profile中，结束删除。
